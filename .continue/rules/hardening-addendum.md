Follow the PROJECT RULES AND HARDENING ADDENDUM for all future work:
1. STABILITY FIRST (Stable > Clever, Predictable > Elegant)
2. NO MAGIC VALUES (name constants and centralize them)
3. CONFIGURATION OVER HARDCODING (tuneable values in config)
4. FAIL SAFE NOT FAIL DEAD (graceful degradation, warn on error)
5. NULL SAFETY (verify existence of objects, entities, etc. before accessing)
6. DEFENSIVE SYSTEM BOUNDARIES (validate incoming data, types, ranges)
7. FUTURE SYSTEM RULE (ensure solutions don't block future expansions like Arcane Door Network, Multiplayer, etc.)
8. EXPLICIT OWNERSHIP (know who creates, updates, consumes, destroys)
9. NO SILENT BEHAVIOR (log unexpected behavior and state transitions)
10. SINGLE RESPONSIBILITY RULE (functions should do one thing)
11. REPEATED LOGIC DETECTION (do not duplicate, extend existing systems)
12. TESTABILITY RULE (ensure fixes are testable)
13. TECHNICAL DEBT WARNING (label temporary solutions with TODO/TEMP FIX)
14. Optimize for future expansion without introducing unnecessary complexity.
